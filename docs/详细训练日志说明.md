# 详细训练日志

三个方法共用的训练入口默认输出原作者风格日志，不需要额外参数。后台运行时会自动写入该任务的 `console.log`，已有 CSV/JSON 指标保持不变。

```text
Client 37 Model Parts: 0-2, Aux Type: tail, P Index: 0
Client 37 Epoch 439 Loss: ...
Epoch 439, Training Time: ..., Training Comm: ..., Test Loss: ..., Test Accuracy: ...
```

- `Model Parts`：本次实际接受、即将训练的主分片闭区间，编号 0～15。预算被拒绝的客户端不输出成功训练信息，剔除原因仍见 `rounds.jsonl`。
- `Aux Type/P Index`：本次计划的额外蒸馏学生类型和位置，不是任务路径已有的边界头尾。无额外学生时显示 `None`；存在学生但权重为零时，不代表实际执行了蒸馏，实际步数见 `rounds.jsonl` 的 `student_steps`。
- `Epoch`：与原作者一致，使用 **0 基全局轮次**；原有简报仍显示 1 基完成进度，所以 `Epoch 439` 对应“轮 440”。不是每个本地 epoch 单独打印一次。
- 客户端 `Loss`：当前训练已记录的、本轮所有本地 epoch 的样本加权平均任务交叉熵，不包含蒸馏损失。原作者是先按 batch 平均、再按本地 epoch 平均；batch 等大时两者一致，尾 batch 不等大时存在差异，不为日志修改训练统计。
- `Training Time`：截至当前轮的累计**模拟训练秒数**，每轮取成功客户端模拟耗时最大值后累加，不是服务器实际运行时间。
- `Training Comm`：截至当前轮的累计**估算双向通信字节数**，含配置启用时的 IPC 额外上传。原作者只累加单向参数包；这里保留当前项目的双向统计口径，不为相似输出更改指标。
- `Test Loss/Test Accuracy`：聚合后完整主模型在测试集的损失和百分制正确率，`73.3` 表示 73.3%，不是 0.733。

输出采用立即刷新；分片信息在训练前输出，损失在该客户端完成后输出。保留原有方法名、seed、完成轮数简报，便于区分三种方法。

本次只改本地代码，不会改变已启动的云端进程；旧日志不会补出历史打印。需要同步新版后启动新任务才能实时看到这些行。现有源码一致性检查会拒绝直接用修改后的源码恢复旧任务，请勿为补日志覆盖正在训练的目录或关闭检查。
