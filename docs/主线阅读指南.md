# 主线阅读指南

不必先通读所有工具文件。先以客户端负责 [3,6]、额外学生 T4 为例，看三个层级。

## 1. 一次实验：experiment.py

`Experiment.prepare()` 做一次性的准备：播种 → 数据 → 划分 → loader → 全局模型 → 成本表 → 轮次执行器 → 结果记录器。

`Experiment.run()` 只有全局轮次循环。它不自己决定选择哪个学生，也不自己计算 IPC，因此所有变体共用同一流程。

## 2. 一轮训练：federation/round.py

`RoundRunner.run()` 用编号注释对应 6 步：

1. 资源变化、抽参与客户端。
2. 清零本轮预测计数。
3. 逐客户端：选择区间 → 核对实际预算 → 本地训练 → 接收更新。
4. 全局聚合与成熟度、队列更新。
5. 完整模型测试。
6. 返回记录，交给结果模块保存。

这与原作者“选客户端、逐客户端训练、轮末聚合、测试”的实验顺序一致。某客户端训练完成后不会立刻改变服务器权重；下一位客户端仍复制同一轮初始权重。

选择学生、预算和打分放在 `strategies/allocation.py`。变化的是策略，而不是循环。

资源有 actual 与 reported 两份。事件模式按 reported 分配，客户端按 actual 再检查；预算不满足则拒绝并报告，不能偷偷训练超预算模型。

## 3. 一个客户端：federation/client.py

`ClientTrainer.prepare()` 构造独立的本地副本和两个优化器。

```text
任务：E → H2 → B3 → B4 → B5 → B6 → T7 → D
学生：T4
```

- 任务优化器包括 E、H2、B3～B6、T7、D 的参数。
- 学生优化器只包括 T4，不包括上述任务组件。
- 服务器 bank 不被客户端原地修改，回传的是 CPU 状态副本。

`ClientTrainer.train()` 控制本地 epoch 和 batch，统计样本加权平均损失、任务步骤数、有效学生步骤数。

`train_batch()` 是最关键的细粒度入口：

1. 清空任务梯度。
2. 本地任务路径前向，保存 logits、E 后特征和学生所需目标。
3. CE 反向；可选保存首批主参数梯度。
4. 用 detached 教师特征/输出构造学生损失。
5. 任务优化器 step。
6. 学生损失乘 λ，反向、裁剪、学生 step。

学生侧使用任务更新前的冻结 D 副本，避免目标和分类器时刻错位。头学生使用已计算的 E 后特征，不再重复训练 E 的归一化状态。λ=0 时不执行学生前向/step。

## 4. 三个策略文件分别改什么

### strategies/allocation.py

`candidates()`：统一候选区间和成本。`select()`：动态最小分数、随机、容量贪心、完整模型、固定区间。`score_terms()`：资源、成熟度、覆盖、时间四项分别返回，便于消融和日志审查。

`commit()` 更新本轮候选覆盖与预测次数。实际累计次数由进度模块在成功训练后更新。选择失败不增加训练次数。

### strategies/distillation.py

`select_student()` 负责选头/尾与位置；`student_weight()` 负责 λ；`compute_student_loss()` 负责 MSE/KL。改损失或固定权重，无需修改联邦循环。

### strategies/aggregation.py

普通 `mean` 对同组件状态按样本量平均，再与旧状态融合。

`gradient_mean` 和 `ipc` 使用同一首批梯度口径，只区别是否除以入选概率。未出现的分片梯度视为 0，不对 q/p 重新归一化。

两条梯度路线的 E/D、辅助模块及 BN 缓冲区仍走状态平均，不能把它们全部叫成无偏梯度估计。

## 5. 状态与记录不是策略

`tracking/progress.py` 只维护 48 个 B/H/T 组件的计数、任务损失代理、成熟度及 Q/M/G 队列，不选择区间。

`tracking/artifacts.py` 只记录结果与哈希，不影响训练。最终聚合是否成功、实验是否完成，以 `summary.json` 是否生成和原始轮次记录为准。

## 6. 为什么要隔离随机数

资源、参与者、分配使用独立 RNG；每客户端每轮训练有独立种子。数据增强按客户端/轮次/epoch/样本播种，并覆盖 DataLoader 的批量读取入口。

否则去掉蒸馏会少消耗随机数，让下一批图片增强也变了，这个对照就混入了额外因素。CPU/CUDA 学生随机流还与任务随机流隔离；MPS 同样保证尚未验证。

相同种子不保证不同算法产生相同权重，但应保证数据划分、初始模型、实际资源轨迹和参与者这些外部条件可核对。
