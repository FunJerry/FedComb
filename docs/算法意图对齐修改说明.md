# 资源、动态评分与 Greedy：修正型原算法

按用户确认：对齐原算法意图，但不复刻疑似实现缺陷；Greedy 对齐原作者模型区间选择，客户端数据划分不改。不是逐数值复现原日志，也不保证更高精度。

## 1. 修改范围

| 部分 | 当前行为 |
|---|---|
| 参与者 | 仍每轮随机选取指定数量，三种方法使用独立且可配对的参与者随机流 |
| 资源 | 只对选中设备，以 20% 概率联合变化；内存 ±20%、算力 ±30%、带宽 ±25% |
| 变化时机 | 分配之前，避免旧脚本分配后资源减少却仍超容量训练 |
| 资源范围 | 不裁剪累积变化；20～120 MB 等范围只是初始抽样范围 |
| 数据 | 保留当前等样本量 Dirichlet，三方法同一 seed 使用同一划分，不恢复原采样器 |
| Greedy | 起点均匀抽 0～15，允许 1～2 片，选该起点下参数包字节数最大的可行区间 |
| Random | 保留长度再起点的一次随机抽样，超预算不重抽 |
| 模型、学习率、蒸馏 | 本次不改架构、温度 2、正确的梯度裁剪顺序和任务/学生梯度隔离 |
| 聚合 | 仅本轮成功训练的更新，绝不复刻旧模型再次参与聚合的风险 |

事件上报协议与实际预算复核均保留；设备可能因服务器报告过期而被拒绝，不暗中取消内存约束。资源发生变化本身不代表服务器已经收到新报告。

配置新增 change_probability、memory_fluctuation、compute_fluctuation、bandwidth_fluctuation，均在 environment 组。旧 fluctuation 字段已移除，旧自定义配置需要显式迁移；不会把一个模糊的幅度静默解释为三个不同幅度。静态资源消融改为 environment.change_probability=0。

## 2. 动态评分：每项可单独审查

目标仍为四项相加、选择最小值，日志 score_terms 分别记录：

1. resource：资源队列 Q 乘模型包利用率与目标利用率之差。
2. maturity：delta=mean(M)，对齐原作者的队列均值口径。主块阈值为 max(0,delta-phi)，辅助阈值为 aux_count_weight*delta；扣除本候选带来的归一化训练次数增量，再乘各组件 M 并取均值。
3. coverage：对全部 16 片计算 `w_G * Σ G_c * (gamma - predicted_coverage_c)`。正号惩罚缺口，不复刻原先负号可能奖励漏覆盖的行为。把候选外的片也计入，避免遗漏项改变区间长度偏好。
4. time：`V * candidate_round_seconds / time_reference`。

覆盖预测在本轮实际成功提交后递增，下一设备能看到已有覆盖；轮开始清零，但不再出现“清零后永远不更新”。本轮预测分母为已接受分配数加当前候选，轮末实际覆盖率分母为本轮全部选中设备数，失败设备贡献 0。空轮只增加覆盖缺口，不假装获得学习更新。

时间参考初值：完整 E→B0…B15→D 在配置初始最低算力和最低带宽下的估算成本，计上下行；之后用本轮最大可行候选成本做 EMA。不是首个设备的成本，也不复刻首次参与 batch_num=0。成本始终由本次样本数、本地 epoch 数和每样本 FLOPs 计算；参考值不是实际硬件测速或所有辅助包的严格上界。

成熟度项沿用原作者启发式门槛，不能据此声称严格最优或收敛保证。若需要研究它，应单独消融或替换公式，而不是混入本次配置变更。

## 3. 成熟度更新和学生计数

- 损失变化改为 `abs(本次首个任务 batch 损失 - 本次最后一个任务 batch 损失)`。
- 参与该客户端训练的组件使用同一任务变化作代理，不宣称得到独立组件损失。
- 客户端样本权重归一化一次；不再额外除参与数。等样本时与原作者算术均值一致。
- 主块计 1，边界辅助计 aux_count_weight，额外学生只有实际蒸馏步数大于 0 才计数。
- 候选评分中的预测次数与提交后的实际次数按同一规则处理；首轮自适应 lambda=0 时学生不计训练，也不上传为已训练状态混入辅助聚合。
- 不保留原 Random/Greedy 忘记更新次数的行为；不同方法都正常更新成熟度。

## 4. Greedy 的准确含义

抽起点 s 后，扫描 e=s…15。每个区间先选配套学生，再计算 E/D、主分片、边界头尾和学生的完整参数包。取可行包中 weight_bytes 最大者；大小相同保留先扫描到的较短区间，与原作者严格 > 的比较一致。

不更换起点、不跨起点优化；不能在第一次超预算时提前停止，因为边界尾和学生可能变化。Greedy 明确不使用 allocation.min_shards 的最少 3 片约束，dynamic/random 仍使用它。这是用户确认的基线定义差异，不能声称三种方法长度约束完全相同。

## 5. 旧模型聚合检查

原作者代码对选择失败设备直接 continue，但聚合时仍遍历 selected_clients 并读取该设备历史 model/end_index，因此旧模型可能再次参加。

当前 RoundRunner 每轮重新建立 updates=[]，只有 trainer.train 成功返回才 append；服务器只接收该列表，模型对象不缓存在客户端身份中。新增回归测试覆盖“上一轮成功、下一轮拒绝”，验证第二轮没有返回旧更新，模型不会再次被改变。

## 7. 建议后续修改（本次没有自动执行）

1. 把原温度 4 与当前温度 2 做独立对照；不要恢复原 AMP 缩放梯度直接裁剪的问题。
2. 如需数值复现，再固定原作者的数据划分、模型初值和参与者/资源轨迹；本次数据划分未修改。
3. 对无界资源漂移做参数讨论，可另外比较有界模型，但不能把它悄悄当成当前规则。
4. 至少 3 个随机种子；同时报告原始最高、最后、末段均值和成功参与率，不只比较平滑峰值。
5. 模拟容量目前只计参数，不是完整训练内存。真实设备验证应另计梯度、优化器、激活和实际网络成本。
